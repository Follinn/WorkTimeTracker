# Табель учёта рабочего времени

Учебное Java-приложение для учёта смен сотрудников, формирования месячных отчётов и расчёта оплаты.

## Возможности

Реализованы модели, хранение смен в месячном табеле, разбиение смен на типы времени
и подсчёт общей длительности и длительности по типам за произвольный период.
Добавлены расчёт оплаты, месячный отчёт и отдельная проверка нормы за период.
Тестами проверены модели, табель, разбиение смен и расчёт за период:
ночные границы, праздники, приоритеты типов, суммирование смен без перерывов,
полночь, граница месяца и оба перевода часов в `Europe/Berlin`.
Этот часовой пояс используется в тестах; пример в `Main` работает с `Europe/Moscow`.

- Учёт сотрудников и смен.
- Разделение времени на обычное, ночное, сверхурочное и праздничное.
- Отчёт за месяц с суммой оплаты в копейках.
- Учёт смен через полночь и обоих переводов часов.
- Проверка нормы рабочего времени.

## Правила расчёта

| Тип времени | Условие | Коэффициент |
| --- | --- | ---: |
| Обычное | Остальное время | 1,0 |
| Ночное | 22:00–06:00 | 1,2 |
| Сверхурочное | После 8 отработанных часов за местные сутки | 1,5 |
| Праздничное | Дата входит в список праздников | 2,0 |

При совпадении условий приоритет такой: **праздничное → сверхурочное → ночное → обычное**. Коэффициенты учебные. Длительность считается по фактическому времени, оплата округляется до копейки один раз за месяц (`HALF_UP`).

## Структура

- `src/model` — сотрудники, смены, табель и отчёт.
- `src/service` — разбиение смен, подсчёт времени, оплата и проверки.
- `src/exception` — исключение при превышении нормы.
- `src/Main.java` — пример запуска.
- `test/model`, `test/service` — unit-тесты JUnit 5.
- `pom.xml` — конфигурация Maven для Java 21 и каталогов `src`/`test`.

## Сборка и проверка

Требуются JDK 21 и Maven 3.9 или новее. Основной код находится в `src`,
тесты JUnit 5 — в отдельном каталоге `test`; существующие пакеты сохранены.
При первом запуске Maven требуется доступ к интернету для загрузки зависимостей.

```bash
mvn clean test
mvn compile exec:java
mvn javadoc:javadoc
```

Команды выполняются из корня проекта. Maven должен быть установлен и доступен
как `mvn`; проверить окружение можно командами `java -version` и `mvn -version`.
Результаты сборки находятся в `target`, отчёты тестов — в `target/surefire-reports`.
Сгенерированную Javadoc можно открыть в браузере: `target/reports/apidocs/index.html`.

## Пример запуска

`Main` демонстрирует три смены Константина в `Europe/Moscow` при ставке
30 000 копеек в час: 25 сентября 09:00–13:00 и 18:00–23:00, а также
26 сентября 22:00–27 сентября 02:00. Только для примера 26 сентября
2026 года объявлено праздничным днём.

Ожидаемый результат: 780 минут работы — 480 обычных, 60 сверхурочных,
120 ночных и 120 праздничных. Оплата — 477 000 копеек.
За отдельный период 25 сентября 21:00–23:00 учитывается 120 минут.
Проверка условной нормы 12 часов сообщает о превышении, после чего
программа продолжает работу и выводит месячный отчёт.

## Тесты

JUnit 5 проверяет валидацию, пересечения и соприкосновения смен, выбор сотрудника,
ночные границы, праздники, приоритеты типов, накопление сверхурочных без перерывов,
полночь и границу месяца, оба перевода часов, пересечения с произвольным периодом,
оплату и однократное округление, пустой табель, норму и её превышение.
Ожидаемые длительности и суммы задаются в тестах независимо от алгоритма.
`Main` служит демонстрацией и не заменяет unit-тесты.

## Учебные допущения

Правила выше являются учебной моделью, а не реализацией трудового законодательства.
Ночь начинается в 22:00 включительно и заканчивается в 06:00 исключительно.
Праздники задаются `Set<LocalDate>`. Дневной порог настраивается и в примере
равен 8 фактически отработанным часам. Несколько смен одного сотрудника
за местные сутки суммируются, перерывы не учитываются. Даты и часы определяются
в часовом поясе табеля, фактическая длительность — через `Instant`.
Сотрудники различаются по ID; ID и ставка должны быть положительными.
Пересечения смен одного сотрудника запрещены, соприкосновения допустимы.
Табель хранит полные смены, пересекающие его месяц, включая переходящие границу месяца.

## Подсчёт времени за период

`TimeCalculator` принимает настроенный `ShiftSplitter`. Его часовой пояс должен
совпадать с часовым поясом табеля. Методы `calculateTotal` и `calculateByType`
получают список полных смен одного сотрудника и границы периода типа `Instant`.
Период `[начало, конец)` включает начало и исключает конец. Совпадающие границы
задают пустой период с нулевым результатом; обратный порядок границ запрещён.

Сначала полные смены разбиваются по типам, затем каждый отрезок пересекается
с периодом. В список нужно включать и более ранние смены тех же местных суток:
они влияют на дневной порог, хотя их длительность за пределами периода
не попадает в результат. Например, у смены 09:00–19:00 в периоде 16:00–18:00
будет один обычный и один сверхурочный час при пороге 8 часов.

`calculateByType` возвращает неизменяемую карту со всеми четырьмя типами;
для отсутствующих типов длительность равна нулю. `calculateTotal` возвращает
сумму длительностей. Расчёт сохраняет секунды и наносекунды, без округления.

## Оплата и месячный отчёт

`PaymentCalculator.calculate` получает сотрудника и длительности по типам.
Секунды вместе с наносекундами переводятся в `BigDecimal`, умножаются на
коэффициенты и суммируются. Затем сумма умножается на ставку и делится на 3600.
Только при этом последнем делении выполняется округление `HALF_UP` до целой
копейки. Результат возвращается как `long`; переполнение вызывает исключение.

`ReportService` настраивается множеством праздников и дневным порогом.
Метод `generateReport(timesheet, employee)` выбирает смены по ID сотрудника
и рассчитывает только их части внутри месяца в часовом поясе табеля.
Ставка переданного сотрудника применяется ко всему месяцу; изменения ставки
внутри месяца в этой учебной модели не учитываются.

`MonthlyReport` хранит сотрудника, месяц, часовой пояс, общую длительность,
неизменяемую карту длительностей всех четырёх типов и оплату в копейках.
Если смен нет, длительности и оплата равны нулю. Сверхурочные включаются
в отчёт независимо от отдельной проверки нормы.

## Проверка нормы

`WorkNormValidator` получает `TimeCalculator` и проверяет смены одного сотрудника
методом `validate(shifts, periodStart, periodEnd, norm)`. Границы периода задаются
через `Instant`, норма — неотрицательной `Duration`. Учитывается только фактически
отработанное время внутри `[начало, конец)`, без перерывов и без умножения
на коэффициенты оплаты. Равенство норме допустимо; превышение даже на наносекунду
вызывает `WorkNormExceededException`.

Норма выбранного периода и дневной порог сверхурочных — разные параметры.
Проверка вызывается отдельно, не изменяет табель и не используется внутри
`ReportService`. Поэтому после обработки исключения отчёт можно сформировать
со всеми сверхурочными часами и их оплатой.
